This lab simulates retry timing for a quick demo: 250 ms → 500 ms → 1000 ms → 2000 ms. It logs the backoff plan instead of actually waiting, so the UI remains responsive.

02 · How to test

  1. Publish a successful event using ID ORDER-1001.
  2. Publish the same ID again to see duplicate protection.
  3. Choose “Always fail” and publish ID ORDER-1002.
  4. Observe retries and the event being sent to the DLQ.
  5. Use Reset to clear the in-memory lab data.

Important: This is a local simulation without Kafka or Docker. Data is held in memory and clears when the application restarts. Use actual Kafka/Docker if your instructor requires broker-backed topics.
